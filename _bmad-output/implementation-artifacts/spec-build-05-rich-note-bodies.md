## Intent

**Problem:** Every template produces thin, index-card bodies — short field sections with no substantive prose. When a graph traversal arrives at a node 2-3 hops out, there is nothing worth reading. The `summary_5` generated by Pass 3 never appears in the note body.

**Approach:** (1) Inject `summary_1` and `summary_5` into the fields map before `render_body` so templates can reference them. (2) Add a `content` field (rich prose, 2-4 paragraphs) to all atomic and container entity templates. (3) Add `overview` and `topics` fields to convergence templates (meeting_summary, email_thread, research_paper, container) — `topics` renders per-topic sections with wikilinks connecting the named entities that converged.

## Boundaries & Constraints

**Always:**
- Pure-atomic types (person, concept, topic, area, note): `content` must be source-agnostic — describes the entity as a durable fact, not "in this meeting X said..."
- Source-bound types (event, task, action_item_list, context, email_thread): `content` and `topics` may reference the specific source document
- Convergence `topics` field uses wikilink format `[[slug.entity_type|Name]]` drawn from the Pass 3 `entities` list — the `%%field%%` description must instruct this explicitly
- `cargo check` and `cargo test --lib` must pass after all changes
- Do not change MCP tool signatures, `anansi_toc` format, or pipeline pass structure
- Do not add new Cargo dependencies

**Ask First:**
- Any change to `Pass3Output` struct that requires updating `parse_pass3_response` or the JSON schema in the prompt file

**Never:**
- Change `prompts/pass-3-node-expansion.md` directly — field descriptions in `%%field%%` blocks drive the prompt automatically
- Add `content` to `outline.md` — outlines are structural scaffolds, not knowledge articles
- Remove or rename `summary_1` / `summary_5` from `NoteRecord` or `Pass3Output`
- Change the `roster_sections` behaviour in container-strategy templates

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Atomic note rendered | Pass 3 returns `content` field with 3 paragraphs | `## Content\n<prose>` appears in note body after existing field sections | If `content` is blank, `## Content\n` renders with empty body — acceptable |
| summary_5 in template | Template body contains `{{summary_5}}` | Substituted with Pass 3's `summary_5` string | If summary_5 empty, renders blank line |

| Re-ingest existing note | Note with new `content` field re-ingested | Pure-atomic merge fills previously blank `content`; source-bound regenerates | Existing content not overwritten if already present (pure_atomic fill logic) |

## Design Notes

**summary_1/summary_5 injection:** These are top-level fields on `Pass3Output`, not in `p3_out.fields`. Cloning the fields map and inserting before `render_body` is the minimal change — no struct modification needed.

```rust
// pipeline.rs — before render_body call
let mut render_fields = p3_out.fields.clone();
render_fields.insert("summary_1".to_string(), p3_out.summary_1.clone());
render_fields.insert("summary_5".to_string(), p3_out.summary_5.clone());
let body_rendered = writer::render_body(&template.body, &render_fields);
```

**Wikilink format in `topics` field:** The `%%field%%` description for `topics` must explicitly state the format: `[[slug.entity_type|Display Name]]` where slug = `slug_name(name)` and entity_type matches the template type. The LLM draws names from its own `entities` list in the response. Example line:
```
[[ron-nishihara.person|Ron Nishihara]] and [[hawaiian-electric.organization|Hawaiian Electric]] discussed grid resilience.
```

**pure_atomic `content` is source-agnostic:** For person/concept/topic/area, the `%%field%%` description must say "Do not reference this specific document — write as a durable, source-agnostic entry." The merge logic already fills blank fields from new sources without overwriting existing values, so the first good `content` written for an entity persists and gets enriched on subsequent ingests.

**Convergence `topics` is long-form:** A 74-leaf meeting could produce a very long `topics` field. This is intentional — the convergence note is the full narrative. LLM context limits may truncate on small models (gemma4:e2b). gemma4:latest should handle it.
